## Linux

Нужны полный JDK 17+, bash, графическая сессия OpenGL и отдельный non-Steam `desktop.jar` ровно 160.7 с Linux natives. Для виртуального дисплея можно отдельно подготовить Xvfb/Mesa. Файлы игры и пользовательский профиль не менять.

Из корня проекта:

```sh
bash work/linux-check.sh /absolute/path/to/desktop-test-160.7.jar full
bash work/linux-check.sh /absolute/path/to/desktop-test-160.7.jar editor
bash work/linux-check.sh /absolute/path/to/desktop-test-160.7.jar power-line
bash work/linux-check.sh /absolute/path/to/desktop-test-160.7.jar item-drop
bash work/linux-check.sh /absolute/path/to/desktop-test-160.7.jar boss-ui
bash work/linux-check.sh /absolute/path/to/desktop-test-160.7.jar notices
bash work/linux-check.sh /absolute/path/to/desktop-test-160.7.jar dense
bash work/linux-check.sh /absolute/path/to/desktop-test-160.7.jar layout
bash work/linux-check.sh /absolute/path/to/desktop-test-160.7.jar wave
bash work/linux-check.sh /absolute/path/to/desktop-test-160.7.jar plus
bash work/linux-check.sh /absolute/path/to/desktop-test-160.7.jar god
bash work/linux-check.sh /absolute/path/to/desktop-test-160.7.jar both
```

Скрипт проверяет версию, собирает обе редакции, создаёт новый каталог `work/linux-check.*`, задаёт отдельный `XDG_DATA_HOME`, компилирует те же инструментированные сценарии и ограничивает ожидание 90 секундами. Завершает только собственный PID. Фикстуры JPEG/BMP в `work/fixtures` созданы для этого проекта на Windows и не являются сторонними ресурсами. Скрипт написан на Windows, синтаксис/работа на Linux ещё не подтверждены.

Ожидаются маркеры всех обязательных локальных сценариев без `_FAIL`, отдельная/совместная загрузка, `routes.png`, `visuals.png`, изображения входа/дисплея и `isolated-world.msav` внутри нового профиля. В `editor` — сохранение клеток после штатного центрирования и импорт только в тестовый менеджер модов. Проверить stdout, stderr и `data/Mindustry/last_log.txt`; сохранить ОС, GPU/driver, Java, SHA-256 JAR и время.

Дополнительно вручную: русские имена файлов/теги, PNG/JPEG/BMP через файловый диалог; clipboard с восстановлением прежнего содержимого; сочетания Ctrl/Alt/Shift; UI scale 100/150/200%, окно 1280×720 и 1920×1080; читаемость/прокрутка, Escape/отмена и сохранение настроек после перезапуска. Для headless создать новый каталог, положить нужную редакцию в `config/mods`, запустить официальный `server-release.jar` 160.7 полным JDK, выполнить `mods`, затем `exit`. Проверить отсутствие загрузки UI и ошибок. Это не объявляет dedicated-функции события поддержанными.

## WAN: собственный host и ванильный гость

На двух отдельных ПК с чистыми тестовыми профилями: God только у хоста, на госте список модов пуст. Штатно открыть матч и настроить доступный владельцу сети способ подключения. Не менять firewall/NAT постороннего оборудования.

1. Проверить вход, отсутствие требования модов, текущие ядра/команды/юниты.
2. Изменить запас ядра, команду, тип/позицию тела, эффект, правило waves и числовое правило. Проверить результат на обоих ПК.
3. Изменить пол/overlay небольшой области, затем отменить. Изменить клетки другим игроком между preview/commit и убедиться в отказе без частичного применения.
   Построить линию энергоузлов обычной очередью и проверить один граф на хосте и госте; повторить с изменением цели/изоляцией до подтверждения.
4. Запустить босса: подготовка, старт, настоящая смерть, возрождение/победа, отключение, поздний вход, reconnect по UUID, замена, ручной результат и следующий раунд.
5. Отключить/включить сервер, загрузить тестовое сохранение: локальные маршруты/AI/повторяющиеся задачи должны сброситься, пресеты остаться. Активный раунд через перезапуск не обещается.
6. Проверить отказ не-хосту, неверные числа/цели, смену карты с открытым подтверждением, несколько клиентов и задержку/потери в управляемой тестовой сети.

Для каждого шага записывать ожидаемое/фактическое состояние обеих сторон и логи. Крупные операции увеличивать постепенно до лимита, измерять задержку кадра и сети. Linux-хост/Windows-гость и обратное направление проверять отдельно.

## CLaJ и updater

CLaJ: выбрать сервис, подтверждённо реализующий используемый конверт/пересылку 160.7, проверить оператора и отсутствие обязательного стороннего контента. Проверить создание/копирование/закрытие комнаты, вход/выход/поздний вход/reconnect, максимум соединений, недоступный/неверный адрес, несовместимый протокол и разрыв relay. Гостю необходим CLaJ-совместимый клиент/адаптер. Прямой vanilla IP/Steam-сценарий проверяется отдельно. Хост видит loopback-адрес моста; IP-бан может затронуть нескольких гостей. Прокси не добавляет шифрование и пересылает трафик по TCP.

Updater: после публикации собственного тестового релиза с корректными именами двух JAR и SHA-256 выбрать этот источник, проверить сведения и скачать без установки. Подменить/повредить кандидат — импорт должен отказать. Проверить явное подтверждение, штатный импорт, перезапуск и откат сохранённым прежним JAR. Не использовать чужой исполняемый мод как тестовую «нашу» сборку. Сетевой отказ/таймаут не должен мешать остальным инструментам.
