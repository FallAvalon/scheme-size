## 3. Подтверждённые условия и оставшиеся расхождения

| Условие / отличие от O279 | Точная причина и поведение | Классификация |
|---|---|---|
| `.mtls` 512² нельзя обещать ванильному читателю | Формат msch сохраняется, но `Schematics.read` 160.7 ограничивает размер; наш bounded codec читает 512². Гостю не нужно читать файл схемы: он получает штатные изменения мира. | Ограничение native reader, проверено отказом и сверено с точным исходником |
| Большие операции не являются полным откатом карты | Пакетность предотвращает единичный сетевой/кадровый всплеск. При позднем конфликте оставшееся прекращается, уже применённое сохраняется; undo хранит последние 16 пакетов. Это показано до подтверждения. | Явная граница транзакции, разрешённое §4.2/§6 ограничение; **не предел площади игры** |
| 16 МиБ файл / 32 МиБ распакованного msch; 512 по стороне; до 3 записей на клетку | Защита чтения и памяти; повреждённый/более крупный вход отвергается, оригинал не меняется. O279 не имел этих защит. Максимальные 786432 короткие записи проверены; произвольный объём конфигураций не обещается. | Защитные границы проекта, а не приписываемые игре ограничения |
| Метка не удостоверяет O279/Plus/God и не даёт прав | Клиент может заявить любой текст. Нет ответа = неизвестно. Строка до 80 символов, без управляющих символов; до 256 записей; rate limits. Старые цвета очищаются. | Намеренная безопасная адаптация; бинарный interop остаётся проверкой категории 2 |
| Прогноз волн/маршрутов не является будущей симуляцией | Точные правила/тип/точки могут измениться; дополнительные сегменты и конкретный наземный core-filter нескольких ядер требуют оговорок. Базовое здоровье не включает боевые множители. Маршруты ограничены бюджетом и известным состоянием карты. | Граница read-only модели; сообщение о частичном итоге, без ложной точности |
| Нет обхода чужого сервера через SlashJS/Darkdustry | Нет подтверждённого совместимого server backend для 160.7. ТЗ §4.5 делает интеграции условными; основной путь — native собственный host. | Недоступное внешнее условие, не незавершённая панель команд |
| CLaJ / updater | Локальные wire/bridge/reconnect и импорт прошли; нет выбранного публичного relay и опубликованного канала проекта. Vanilla IP/Steam не требует CLaJ-адаптера; сам CLaJ требует его на госте. | Внешние проверки, [точный план](06_external_test_plan.md) |
| Linux | `wsl --status` exit 50, bash/Docker/Podman отсутствуют; подготовлен `work/linux-check.sh`. | Непроведённая платформенная проверка, не доказанная поддержка |
| WAN | Нет второго управляемого внешнего ПК/NAT; локальная сеть/loopback не доказывает WAN. | Непроведённая сетевая проверка |
| Ручной OS-ввод агентом | Sky не перечисляет именованное окно отдельного тестового процесса; пользовательский Steam-профиль не использовался для обхода. | Непроведённая проверка ввода; пользователь может пройти шаги ниже |

Android и шуточный Backdoor исключены ТЗ, а не забыты. Глобальные input/GlyphLayout не подменяются: функциональные замены и причины перечислены в матрице. Проверенные временные очереди/активный раунд не обещаются сохраняемыми после перезапуска; локальные схемы и пресеты сохраняются.

## Короткая ручная приёмка

Из корня проекта можно запустить **отдельный профиль без тестовых observer-модов**:

```powershell
./work/user-acceptance.ps1 -Edition plus
./work/user-acceptance.ps1 -Edition god
# Отдельный процесс для гостя с пустым списком модов:
./work/user-acceptance.ps1 -Edition vanilla
# Необязательно, для совместной установки:
./work/user-acceptance.ps1 -Edition both
```

Каждая команда создаёт новый `work/acceptance-<edition>-<uuid>` и показывает путь/свой PID. Используется подготовленная отдельная копия 160.7, установленная игра и основной профиль не меняются. Команда запускает видимую игру; автоматический пользовательский проход не заявляется выполненным. Для повторного входа используйте уже созданный отдельный профиль, а не новую команду с другим UUID. Закрывайте игру штатно.

Синтаксис нового launcher проверен PowerShell Parser; его ручной пользовательский запуск не засчитан как пройденный OS-тест. Загрузка обычных артефактов и изоляция профиля отдельно проверены unwrapped runner.

После закрытия — повторный запуск того же профиля: `./work/user-acceptance.ps1 -Edition god -Resume 'C:\DiskSpasenie\ShemeSize\work\acceptance-god-ВАШ_UUID'`. Для Plus/vanilla/both укажите исходную редакцию и её каталог. Сохранённые JAR/UUID/настройки остаются прежними; логи повторного запуска получают уникальные имена, указанные в `session.txt`.

1. В меню «Моды» проверьте название редакции. Начните отдельную песочницу. Кнопка **S+** у Plus или **SG** у God должна открывать инструменты. В `both` — один общий HUD, редакция God. Нет красной ошибки загрузки/двойных действий.
2. «Схемы» → выбрать слой → выделить небольшую область → сохранить копию → экспорт/импорт файла и Base64 → «Использовать». Проверьте содержимое, поворот и отмену штатного preview. «Быстрые схемы» → точный тег: нужная схема должна остаться в списке.
3. Для нового dense-сценария используйте собственные [схему зданий](../work/ui-probe/run-0fdbae03643e4cfab8c21b2747f6c127/dense-buildings.mtls), [три слоя ландшафта](../work/ui-probe/run-0fdbae03643e4cfab8c21b2747f6c127/dense-terrain.mtls), [здания на границе](../work/ui-probe/run-0fdbae03643e4cfab8c21b2747f6c127/boundary-buildings.mtls). Полный preview зданий должен запросить подтверждение; отмена не ставит планы. Участок 0/0/128/4 граничной схемы содержит первое многоклеточное здание, участок 128/0/128/4 — второе. Для полного ландшафта нужна **тестовая карта хотя бы 512² со свободной областью**: задайте нижний левый X/Y, подтвердите число клеток/пакетов, следите за счётчиком. Отмена останавливает оставшееся; уже изменённое остаётся. На маленькой/занятой карте ожидается отказ без начала вставки.
4. «Изображение» → PNG/JPEG/BMP → небольшая раскладка дисплеев → преобразовать → сохранить/разместить. Дайте питание. Картинка должна появиться без ошибок mlog; отмена/неверный файл не должны заменять прежнюю схему.
5. «Строительство» → небольшой контур/заливка/замена, затем предметы и энерголиния. Проверяйте число планов до согласия. «Уничтожить предметы» сначала показывает необратимость. Отмена приоритетного запроса сохраняет уже полученное. «Визуальные слои»/«Маршруты» → включить и выключить: линии клеточные и только локальные, скрытие юнитов не останавливает бой.
6. God: штатно откройте host и подключите vanilla-процесс по локальному адресу/порту игры. Из «Ресурсы» измените небольшой запас, из «Игроки» — команду/телепорт, из «Арена» — пару клеток. Гость видит изменения без требования установить мод. Укажите неверное число или отмените подтверждение — мир не меняется.
7. God: выберите подключённого игрока боссом, разные команды, короткий раунд. Сохраните/загрузите пресет, стартуйте; проверьте объявление гостю, паузу часов, продолжение, смерть/результат, следующий раунд и отмену. Для disconnect/reconnect сохраните тот же отдельный профиль гостя. Проверьте замену босса и возврат команд/множителей.
8. God → «Настройки» → «Раскладки панели организатора»: сохранить имя, изменить положение HUD/модуль, загрузить с подтверждением. Настройки вернулись; мир/событие прежние, локальные задачи остановились. У Plus этой организаторской кнопки нет. Завершите игру и заново откройте **тот же отдельный профиль**: схемы/пресеты/раскладки должны остаться.

Искать: исключения/красный текст загрузки, отсутствующие кнопки, обрезанные подписи/невозможность прокрутить при 100/150/200%, потерю граничных зданий, вставку без согласия, продолжающуюся после отмены очередь, отсутствие синхронизации у гостя, неправильную цель/команду и невозвращённые множители босса.

## Что приложить к сообщению об ошибке

- Редакция и SHA-256 из `session.txt`; Build 160.7, Windows/Linux, UI scale и разрешение.
- 3–5 точных шагов, ожидаемое и фактическое состояние, время ошибки, тип карты/solo/host/guest. Для сети — обе стороны.
- Из созданного `work/acceptance-…`: `stdout.log`, `stderr.log`, `appdata/Mindustry/last_log.txt`, `session.txt`. Скриншот или небольшой собственный проблемный файл схемы/изображения при необходимости.
- Для обычной установки папку данных открывайте средствами игры: Windows обычно `%APPDATA%/Mindustry`, Linux — `$XDG_DATA_HOME/Mindustry` либо `~/.local/share/Mindustry`; нужен `last_log.txt`. Не отправляйте всю папку профиля/сохранений без необходимости.
