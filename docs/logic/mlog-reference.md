# Mindustry Logic: справочник для разработки

## Что это и чем не является

**[ФАКТ]** Mindustry Logic (mlog) — встроенный язык блоков-процессоров, добавленный в V6. Он исполняет команды по одной, в стиле ассемблера; он не является JavaScript модом или Java-плагином. Официальный мануал прямо предупреждает, что пока неполон. [Введение](https://mindustrygame.github.io/wiki/logic/0-introduction/)

## Исполнение и ресурсы процессора

Процессор повторяет программу и за каждый тик исполняет число инструкций `@ipt`. Wiki указывает 60 ticks/second и следующие значения:

| Тип | `@ipt` | Расчётный максимум команд/сек |
|---|---:|---:|
| Micro | 2 | 120 |
| Logic | 8 | 480 |
| Hyper | 25 | 1500 |

Максимум в секунду — простой пересчёт, реальная нагрузка зависит от других блоков и версии.

## Синтаксис программы

```mlog
set count 0
sensor health turret1 @health
jump 5 lessThan health 0.5
control turret1 enabled 0
jump 0 always 0 0
control turret1 enabled 1
jump 0 always 0 0
```

Пример иллюстрирует переменные, чтение поля, условный переход и управление блоком; это учебный набросок, проверяй индексы переходов в Visual Editor конкретного build. `jump` переходит к номеру команды, `@counter` хранит позицию следующей команды. [Writing and Editing Code](https://mindustrygame.github.io/wiki/logic/2-editing/) · [Variables and Constants](https://mindustrygame.github.io/wiki/logic/3-variables/)

## Данные и значения

- `number`: десятичное значение; в truthy/falsy проверках ноль ложно, ненулевое истинно.
- `Building`: ссылка на существующий блок на карте. Не то же самое, что тип блока (`@duo`).
- `Unit`: ссылка на живого юнита.
- `String`: строка; применяется как параметр команд текста.
- Контент-ссылки: `@copper`, `@dagger`, `@scatter` и т. п.
- `set x value` создаёт или обновляет переменную; переменные без заранее объявленной декларации.
- Преобразование number/object может неявно привести к `null` или `1`/`0`; ошибки параметров часто дают отсутствие результата, а не полезное сообщение.

Значение `@this`, `@thisx`, `@thisy`, `@ipt`, `@counter`, `@links`, `@unit`, `@time`, `@tick`, `@mapw`, `@maph` описаны в [Wiki: Variables and Constants](https://mindustrygame.github.io/wiki/logic/3-variables/).

## Основные операции

| Команда/семейство | Роль |
|---|---|
| `set` | назначить значение переменной |
| `op` | арифметика, преобразования и математические функции |
| `jump` | условный или безусловный переход |
| `read` / `write` | чтение/запись в memory cell/bank |
| `getlink` | получить связанное с процессором здание |
| `sensor` | прочитать свойство здания/юнита/контента |
| `control` | отдать поддерживаемую команду зданию (например `enabled`, конфигурация, цель) |
| `radar` / `uradar` | искать цель в радиусе по фильтрам |
| `ulocate` | найти здание/позицию по доступным критериям |
| `ubind` / `ucontrol` | выбрать юнита и отправить команду |
| `print` / `printflush` | собрать и вывести текст через message block |
| `draw` / `drawflush` | нарисовать примитивы/текстуру на дисплее |
| World Logic | сценарные команды вроде изменения карты/правил/эффектов, если включены правилами |

Это категории для ориентации, а не исчерпывающая таблица. Полный набор параметров раскрывается редактором V8. В V8 добавлены возможности вывода текста и преобразования графики, а world processors получили дополнительные возможности. [Официальные заметки V8 Build 147](https://store.steampowered.com/news/posts/?appgroupname=Mindustry&appids=1127400&enddate=1744600127&feed=steam_community_announcements)

## Связи и переменные

- `getlink block 0` получает первый линк; `@links` возвращает число линков.
- `getlink` не равен поиску любого блока на карте: нужен link или доступная инструкция поиска.
- Один процессор одновременно управляет одним bound unit (`@unit`). Для цикла по типам юнитов используют `ubind` и повторяют команды по мере возможностей.
- Переменная-ссылка может запомнить identity юнита для сравнений, но не сохраняет право команды для `ucontrol` после перепривязки.
- В цикле избегай бесполезной высокой частоты опроса, если состояние изменяется редко; используй `wait` или другой паттерн, если это подходит.

## Отладка ошибки

1. Убедись, что процессор запущен и у команды есть право на нужное действие.
2. Проверь точное имя linked block и индекс `getlink`.
3. Выведи промежуточные значения через message block или Display.
4. Проверь, что `sensor` получает ожидаемый тип цели, а поле доступно для этого типа.
5. Подтверди адреса прыжков и то, что цикл имеет условие выхода/паузы.
6. Учитывай build-specific параметры и инструкции.

## Отдельные уровни логики

- **Обычный processor**: автоматизация связанной базы.
- **World processor**: мощные действия мира; обычно зависят от включённых правил/карты.
- **Mlog**: скрипт внутри игры, сохранённый на процессоре/карте.
- **Mod scripts / Java**: внешний моддинг API, запускается в lifecycle игры и имеет другой доступ.
